# Nutritionist Assistant — связанное рабочее пространство

**Дата:** 2026-07-20 · **Статус:** реализовано

## Проблема

Три подмодуля Nutritionist Assistant (каталог продуктов, расчёты RER/MER и Dry Matter,
конструктор диеты) были полностью изолированы:

- каталог (3771 позиция с ME, CP, CFa и др.) нельзя было использовать ни в конвертере
  Dry Matter, ни в конструкторе диеты — данные приходилось перепечатывать;
- MER из калькулятора не передавался в конструктор — целевые ккал вводились вручную;
- конструктор считал граммовку по фиксированной плотности 1.6 ккал/г независимо от
  состава — граммы для овощей и масел были ошибочны в разы;
- каждый инструмент отдельно спрашивал пациента при сохранении, параметры пациента
  не подставлялись в калькулятор;
- состояние конструктора терялось при переключении вкладок (Radix Tabs размонтирует
  неактивный контент).

## Решение

Общий zustand-стор `src/lib/nutrition-workspace.ts` — единый контекст модуля:

- `activeTab` — вкладки управляемые, инструменты могут переключать друг друга;
- `patientId` — общий пациент: панель выбора над вкладками, префилл калькулятора
  из карты (вес, BCS, life stage, активность, кастрация, целевой вес), сохранение
  планов в один клик;
- `targetKcal`/`targetKcalSource` — кнопка «Использовать N ккал в конструкторе»
  в результатах RER/MER; в конструкторе — чип для повторного применения;
- `dmPrefill` — кнопка «Анализ DM» в карточке продукта каталога подставляет
  CP/CFa/CFi/влажность в конвертер; рядом с оценкой по Атуотеру показывается
  каталожная ME и расхождение в %;
- состояние конструктора (`components`, `dailyKcal`, `dietType`) живёт в сторе
  и переживает переключение вкладок; кнопка «В рацион» в каталоге добавляет
  продукт компонентом с реальной ME и макросами (доля — остаток до 100%),
  дубликаты не добавляются.

### Расчёты (`src/lib/nutrition.ts`)

- `buildDietTemplate` — проценты трактуются по BARF-конвенции как доли **массы**
  рациона; общая масса решается так, чтобы суммарная энергия попала в целевые ккал:
  `totalGrams = dailyKcal / Σ(share_i × density_i)`. Плотность компонента — реальная
  ME из каталога (ккал/кг ÷ 1000) или дефолт категории (`DIET_CATEGORY_DENSITY`:
  мясо 1.5, овощи 0.5, масла 8.8, сухой корм 3.6 …).
- `summarizeDiet` — итог: г/день, ккал/день, белок и жир в г/день по компонентам
  с данными каталога + доля массы, покрытая макроданными.

### Типы (`src/lib/types.ts`)

`DietTemplateComponent` расширен: категория `commercial` (готовые корма) и
опциональная связь с каталогом (`productId`, `meKcalPerKg`, `proteinPct`, `fatPct`).
Ручное редактирование имени/категории связанного компонента отвязывает его от
каталога. Сохранённый JSON обратно совместим с рендером в CRM (diet-plan-panel).

### Маппинг категорий каталога → конструктора

белки→protein, углеводы→grain, жиры→fat, клетчатка→vegetable,
сухие/влажные корма→commercial, добавки/лакомства→supplement.

## Итерация 2: поиск в конструкторе + нутриентный анализ

- **Инлайн-поиск каталога в Diet Builder**: поле над кнопкой «Add Component»,
  дебаунс-запрос `GET /api/nutrition-products?q=…` (глобальный поиск по всем
  категориям, до 20 результатов с полными нутриентами), клик по результату
  добавляет компонент через `productToDietComponent` без смены вкладки.
- **`src/lib/nutrition-analysis.ts`**: `aggregateDietNutrients` собирает per-day
  итоги (мг/мкг/г) по связанным продуктам (`GET ?ids=…`), считает белок/жир/НФЭ
  г/день, энергию по модифицированному Атуотеру, Ca:P и ω6:ω3, покрытие массы;
  `buildNormComparison` сравнивает с NRC 2006 (взрослые, на 1000 ккал,
  масштаб — целевая калорийность, вид — от выбранного пациента).
- **Панель «Нутриентный анализ рациона»** под конструктором: стат-плитки
  (белок/жир/углеводы, Ca:P с диапазоном 1.0–2.0, ω6:ω3), стековая полоса
  структуры энергии, прогресс-бары «% от нормы» (шкала до 150%, метка на 100%,
  дефицит <90% — амбер), таблицы итогов по 5 группам, предупреждение при
  покрытии <60% массы, дисклеймер о справочности норм.
- Витамины A и D: единицы каталога неоднозначны («МЕ» без знаменателя) —
  показываются только итогами, в норм-сравнение не входят.
- `NUTRIENT_UNITS` расширен (минералы мг/мкг, витамины мг/мкг/МЕ, амино- и
  жирные кислоты г) — единицы теперь видны и в карточках каталога.

## Проверено (dev-сервер, браузер)

- выбор пациента → чипы (вес, BCS, MER ≈), префилл калькулятора из карты;
- «Анализ DM» → переключение вкладки, поля заполнены, бейдж продукта,
  «каталог: 795 ккал/кг (-2%)» для Бараньего рубца;
- «В рацион» → тост, компонент с меткой каталога; граммовка по ME:
  256 г × 0.795 = 203 ккал, итог точно равен целевым 1726 ккал;
- «Использовать 1726 ккал в конструкторе» → вкладка + kcal применены;
- сохранение рациона пациенту в один клик → POST /api/diet-plans 201,
  macros `{proteinG, fatG}`, template с связанными полями;
- tsc и eslint — 0 ошибок; консоль браузера чистая.

Итерация 2:
- поиск «печень» → выдача по всем категориям (сухие/влажные корма, добавки) с ME;
  «Куриная печень» добавлена кликом, тост показан;

- предупреждение о покрытии 20% массы отображается; все 5 групп итогов рендерятся;
- tsc/eslint 0 ошибок, консоль чистая.

## Итерация 3: только каталог + графики по группам

- Ручные записи убраны полностью: нет «Add Component», нет пресетов
  (BARF Dog / Home-Cooked / Puppy BARF) с текстовыми ингредиентами, стартовый
  рацион пуст. Название компонента — только из каталога (текст, не input;
  рядом ME ккал/кг); редактируются категория и доля, строку можно удалить.
  Пустые состояния в конструкторе/составе/сохранении; сохранение пустого
  рациона заблокировано.
- Ранжирование поиска `?q=`: `ORDER BY instr(searchName, q), length(name), name`
  — сырьё («Морковь») выше брендовых кормов, упоминающих его в названии.
- Панель анализа: вместо прогресс-строк и плиток — пять recharts-графиков
  (горизонтальные бары, barSize 14, radius 3, прямые подписи значений, кастомный
  тултип «значение · норма», референс-линия 100% в %-графиках, шкала до 300%
  с фактическим % в подписи, Cell-заливка: дефицит <90% — амбер, иначе тил):
  Основные (г/день), Минералы (% нормы, 12 позиций), Витамины (% нормы, 9 позиций
  + справочные плитки A/D/C/B7), Аминокислоты (г/день), Жирные кислоты (г/день).
- Нормы дополнены: Cl, J, B4 (холин), B5; клетчатка агрегируется (CFi);
  AA добавлена в агрегацию (исправлен расчёт ω6:ω3, где AA всегда была 0).
- Проверено в браузере: рацион 100% из каталога (бедро бройлера 60% + куриная
  печень 10% + морковь 30%) — 6 графиков, Ca 19% амбером, Na 629% в подписи при
  обрезанной шкале, легенда и дисклеймер на месте; tsc/eslint 0, консоль чистая.
