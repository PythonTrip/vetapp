# Дизайн: структурированный анамнез и редактируемая история обращений

Дата: 2026-07-20

## Проблема

1. Анамнез в карточке приёма — одно большое текстовое поле. Врач каждый приём заново
   печатает повторяемые данные: возраст, активность, кормление, аллергии, хронические
   состояния.
2. Повторяемые данные нигде не хранятся структурированно: у `Pet` есть только `notes`.
3. История обращений (Timeline) — просмотр «сырых» notes и удаление. Редактировать
   завершённый приём и его анамнез нельзя; структурные секции (осмотр, диагнозы,
   назначения) не отображаются.

## Решение

### 1. Паспорт пациента — источник повторяемых данных

Расширяем `Pet` (Prisma, SQLite → JSON в строках, по образцу `diagnoses`):

- `allergies String @default("[]")` — массив строк («Курица», «Пыльца берёзы»…);
- `chronicConditions String @default("[]")` — массив строк;
- `feeding String?` — JSON-объект `{ foodType, brand, dailyAmount, feedingsPerDay,
  treats, supplements, notes }`.

`pet-form.tsx` получает chip-ввод аллергий (подсказки из справочника) и хронических
состояний + блок «Кормление». Эти данные вводятся один раз и дальше автоматически
подставляются в каждый анамнез.

### 2. Структурированный анамнез приёма

`Consultation.anamnesisData String?` — JSON `{ specialty, answers: {fieldId: value} }`.
Существующее текстовое поле `anamnesis` сохраняется: в него пишется автоматически
сгенерированная текстовая сводка (совместимость с отчётами, share-страницей, AI).

`src/lib/anamnesis-schema.ts` — декларативные наборы полей:

- **Дерматология**: давность симптомов, течение, сезонность, локализация (chips из
  BODY_REGIONS), обработки от эктопаразитов, контактные животные/люди, прежнее лечение
  и ответ, содержание/среда.
- **Диетология**: цель обращения, аппетит, стул, рвота, поедание со стола/лакомства,
  доступ к чужой еде, потребление воды, динамика веса со слов владельца, история рационов.
- Типы полей: `select`, `chips` (мультивыбор кнопками), `text`, `toggle`.

`src/components/crm/anamnesis-form.tsx`:

- Панель «Из карточки пациента» — возраст (вычисляется), пол/кастрация, активность,
  BCS/вес, аллергии, хронические, кормление. Только чтение + кнопка «Изменить карточку».
  Врач ничего не перепечатывает; сводка включает эти данные автоматически.
- Поля по выбранному направлению (дерматология/диетология/общий), компактные контролы.
- Кнопка «Скопировать из прошлого приёма» — переносит ответы последнего приёма того же
  направления, врач правит только изменившееся.
- Свободное текстовое поле «Дополнительно».

`consultation-workspace.tsx`: textarea анамнеза заменяется на `AnamnesisForm`;
шаблоны (системные и пользовательские) заполняют структурированные ответы через
`sections.anamnesisAnswers`; при сохранении в приём уходят `anamnesisData` + сводка.

### 3. История обращений: просмотр и редактирование

`consultation-timeline.tsx`:

- записи раскрываются: структурированный анамнез (метка → значение), осмотр,
  диагнозы (badges), назначения (таблица), контрольный план;
- кнопка «Редактировать» открывает `consultation-edit-dialog.tsx` — полный редактор
  (дата, тип, направление, жалоба, вес, VAS, AnamnesisForm, осмотр, диагнозы,
  назначения, контроль) с PATCH через `useUpdateConsultation`;
- исправление бага: `useDeleteConsultation` в hooks.ts использует сломанный URL
  `` `\api\consultations\${id}` `` — удаление записей не работает.

### API

- `POST/PATCH /api/pets*`: принимают `allergies`, `chronicConditions` (массивы →
  JSON.stringify), `feeding` (объект → JSON.stringify);
- `POST /api/pets/[id]/consultations`, `PATCH /api/consultations/[id]`: принимают
  `anamnesisData` (объект → JSON.stringify).

### Вне объёма

Отдельная сущность Client/Encounter (полный pivot доменной модели), миграция
существующих текстовых анамнезов в структуру, версия anamnesis-схемы.

## Критерии готовности

- Повторяемые данные вводятся один раз в карточке пациента и автоматически видны в
  анамнезе каждого приёма.
- Дерматологический и диетологический анамнез заполняется преимущественно кликами
  (select/chips), с копированием из прошлого приёма.
- Любую запись истории можно раскрыть, отредактировать и удалить.
- Lint без ошибок, сквозной сценарий проверен в браузере.
