# Мобильный кабинет владельца

Срез реализации на 2026-11-01. Это локальное расширение существующей клинической системы, а не замена её визуальной идентичности. Продуктовые состояния и серверные ограничения остаются описанными в [consultation-ux.md](consultation-ux.md); целевые правила — в [design.md](../design.md). Оба документа и shared-токены сохранены.

## Поверхность и навигация

`apps/owner-web/src/app/page.tsx` перенаправляет `/` на `/cabinet`; `cabinet/page.tsx` открывает `CabinetHome`. Внутри кабинета используются hash-разделы `#home`, `#visits`, `#pets`, `#results`, `#chat`, `#profile`, синхронизированные с `hashchange`. Нижняя навигация содержит главную, питомцев, сообщения и профиль; консультации и результаты сохраняют активной главную. «Все» и «Подробнее» открывают консультации, «Медкарта» — результаты завершённых приёмов, «Сообщения врачу» — переписку.

`packages/owner-features/src/components/animal-list.tsx` хранит выбранный UUID питомца в состоянии компонента; при отсутствии выбора используется первый питомец. Выбор общий для паспорта, консультаций, результатов и чата. На главной питомец выбирается по аватару, в остальных разделах — через select. Это состояние не записывается в URL или постоянное хранилище. Форма записи допускает выбор другого питомца; после успешной отправки кнопка «К консультациям» закрывает форму и передаёт выбранный UUID родителю, но сама по себе hash-раздел не переключает.

На главной сначала показана текущая консультация: активный приём имеет приоритет, далее используется время. Следом идут до двух остальных предстоящих записей, основное действие записи и быстрые действия. Чат относится к выбранному питомцу; отдельного чата визита нет. Без подключённого врача интерфейс предлагает подключить его в профиле.

## Четыре шага записи

Форма реализована в `packages/owner-features/src/components/visit-request-form.tsx`:

1. Питомец, причина до 4000 символов, тип обращения и опубликованная анкета. Все вопросы обязательны; ошибка загрузки анкеты блокирует переход и предлагает повтор. Смена типа перезагружает вопросы и сбрасывает ответы.
2. Единственный врач, уже подключённый к кабинету. Карточка подтверждает контекст; каталога врачей, рейтингов и выбора другого специалиста нет.
3. Предлагаемые дата и время, фото и документы. `booking-date-picker.tsx` предлагает шесть следующих дат и редактируемое поле `datetime-local`; это предпочтения, а не свободные слоты. Часовой пояс — устройства, отправка — ISO UTC. API доступности отсутствует; окончательное время подтверждает врач. Допустимы непустые JPEG, PNG, WebP, GIF, PDF до 8 МБ каждый.
4. Проверка питомца, типа, врача, причины, времени, ответов и файлов; отправка заявки. До создания заявки можно вернуться назад. После успеха показывается подтверждение ожидания решения врача.

Создание заявки предшествует последовательной загрузке файлов. UUID созданной заявки сохраняется, успешные файлы немедленно удаляются из очереди. При сбое повтор загружает только оставшиеся файлы в ту же заявку. После создания поля заблокированы; ошибка явно сообщает, что заявка уже создана. Этот механизм не заменён визуальным сценарием.

## Реальные связи с API

Пути ниже определены в `packages/owner-features/src/api.ts`; `ownerRequest` добавляет префикс `/owner`. Авторизация и проксирование используют существующий механизм.

| Назначение | API |
| --- | --- |
| Сессия и профиль | `GET/PATCH /owner/me`, `POST /owner/login`, `/owner/logout` |
| Подключение врача | `POST /owner/connect-doctor` |
| Питомцы | `GET /owner/animals` |
| Вопросы по типу визита | `GET /owner/visit-questions/{type}` |
| История и создание заявки | `GET/POST /owner/animals/{animalId}/visits` |
| Отзыв и отмена | `POST /owner/visits/{id}/withdraw`, `/owner/visits/{id}/cancel` |
| Материалы заявки | `POST /owner/visits/{id}/files`, `GET /owner/visits/{id}/files/{fileId}` |
| Общие файлы питомца и скачивание результата | `GET /owner/animals/{animalId}/files`, `GET /owner/files/{id}` |
| Переписка питомца | `GET/POST /owner/animals/{animalId}/chat` |

Список визитов обновляется каждые 30 секунд при видимом документе, при возврате во вкладку, восстановлении сети и вручную. Изменения статуса, времени, encounter и списка результатов объявляются через `role=status`. Время само не начинает и не завершает приём: подписи вычисляет существующая `consultationState` в `packages/owner-features/src/domain.ts`.

Результаты используют прежний `result_files` и авторизованное скачивание через `platform.saveFile`, включая Telegram. Нужны точная привязка результата к приёму и явный доступ владельцу; общие материалы питомца не становятся результатами автоматически. Отсутствие файлов означает «Пока недоступны», а не фоновую генерацию. Перенос обсуждается в чате; отдельного endpoint переноса владельцем нет. Серверные ограничения отмены и история только по заявкам остаются прежними — см. [consultation-ux.md](consultation-ux.md).

## Визуальная преемственность и доступность

`packages/owner-features/src/styles.css` изолирует оформление owner-поверхности. Экспорт `@vetdietderm/owner-features/styles.css` импортируется обоими `apps/owner-web/src/app/globals.css` и `apps/clinic-web/src/app/globals.css`: клинический `/cabinet` также использует общий `CabinetHome`. Его `surface-boundary.tsx` получает те же обёртки `owner-app`/`owner-app-content`; ветки `/join` сохранены. Контент ограничен 720 px; боковые поля — 16 px, от 768 px — 24 px. Фиксированная нижняя навигация учитывает safe area; основной контент имеет нижний отступ. Диалог ограничен 540 px и высотой viewport, прокручивается; снизу закреплено основное действие высотой 52 px. У кнопки возврата компактная иконка с доступным именем «Назад», область нажатия 44 px.

Цветовая истина runtime — только `packages/ui/src/styles.css`: `--background`, `--foreground`, `--card`, `--primary`, `--primary-foreground`, `--accent`, `--muted-foreground`, `--border`, `--input`, `--ring`, `--destructive`. Карточки используют `--card`/`--accent`, основное действие — `--primary`/`--primary-foreground`, фокус — `--ring`. Значения не копируются в отдельную палитру; тёмная тема наследует существующие переменные. Декоративный SVG-паттерн из предоставленного HTML адаптирован к этим ролям в `cabinet-visuals.tsx`; shipping-растров нет. Инициалы владельца, питомца и врача получены из реальных имён. Поля фотографии в паспорте нет, поэтому стоковые изображения не подменяют питомцев.

Основной шрифт owner web остаётся `Arial, Helvetica, sans-serif`; заголовки шагов локально используют `Georgia, "Times New Roman", serif` (28/30 px). Это решение конкретной поверхности, а не глобальный display-стандарт. Поля используют 16 px; focus-visible получает явный контур, выбор питомца и типа обозначен `aria-pressed`, ошибки — `role=alert`. Анимация открытия включается только при отсутствии запроса reduced motion.

`booking-sheet.tsx` использует нативный `<dialog>` и `showModal()`: браузер удерживает фокус и делает фон inert. Переход между шагами фокусирует заголовок, закрытие возвращает предыдущий фокус и восстанавливает прокрутку body. Escape, клик по области самого диалога и крестик закрывают его; во время создания заявки или загрузки файлов закрытие защищено флагом busy, крестик отключён, Escape отменён. Это не механизм сохранения черновика.

Существующее расхождение цели и runtime сохранено явно: [design.md](../design.md) задаёт целевую hex-палитру, тогда как shared CSS использует ранние OKLCH-значения и имена `--foreground`/`--card`; shared `Button` и `Input` имеют базовую высоту `h-9`, а owner-поверхность повышает touch minimum до 44 px. Целевые размеры, веса, радиусы и типографика не полностью совпадают с реализацией; подписи навигации, прогресса и календаря местами 12 px. Это описание наблюдаемого состояния, не утверждение нового глобального стандарта. Проверены shared `styles.css`, `button.tsx`, `input.tsx`, owner `globals.css`, общий `owner-features/src/styles.css` и предыдущая фиксация drift в `consultation-ux.md`; глобальные файлы не переписаны.

## Проверка и границы вердикта

Переданные результаты проверки: 27 owner-тестов, lint и typecheck прошли; финальная production-сборка owner Webpack после трёх визуальных исправлений прошла. Turbopack аварийно завершается в данной среде. После выделения неизменённого CSS в общий пакет прошли также 47 clinic-тестов; повторные production-сборки обоих приложений через Webpack завершились успешно (exit 0). В `apps/owner-web/package.json` явно добавлен `@types/node: ^26.4.0` с использованием уже существовавшего пакета lockfile.

Браузерная проверка использовала изолированные mock-ответы API: отправка, переход в чат и Escape прошли без ошибок. Снимки 390×844 и 1440×1000 находятся в `.impeccable/review/mobile-cabinet/`; это проверочные материалы, не production-данные и не shipping-ассеты. На 390×844 подписи быстрых плиток всё ещё требуют короткой прокрутки.

Финальный finish-review: **ship** только в пределах трёх исправлений, оценённых как resolved: обрезание CTA, видимость основного действия записи над нижней навигацией и компактная кнопка возврата. Это не повторный полный визуальный аудит и не заключение о всём репозитории.
